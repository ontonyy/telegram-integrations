# Заготовки задач Telegram для CVNoor API

**Статус:** предложено, Jira-ключей нет. Это не планы исполнения. Перед созданием тикета перечитать в нужной ветке `docs/plans/README.md`, текущий `CLAUDE.md`, API/OpenAPI-контракт и матрицу проверок. Правила backend требуют, чтобы у каждого плана реализации была ссылка на Jira; добавить её при превращении заготовки в реальный план.

## Решения и контракты

| Ссылка | Результат будущего тикета | Готово, когда | Зависимость/ограничение |
|---|---|---|---|
| API-TG-01 | Выбрать область уведомлений и тип провайдера | Решены Bot API/Business, получатели, категории событий, начало диалога, провайдер и исключения | Продукт/владелец/поддержка; без секретов |
| API-TG-02 | Описать контракт привязки Telegram к пользователю | Короткая одноразовая привязка только аутентифицированного CVNoor-пользователя; описаны отзыв, unlink и защита повтора | Clerk-контракт; определить владельца API и приватности |
| API-TG-03 | Описать контракт предпочтений и согласия | Настройки отдельно по целям, времена согласия/отказа, язык, получатель, срок и подавление | Решения продукта/юриста/приватности и защита молодых пользователей |
| API-TG-04 | Описать контракт события и доставки | Типы событий, минимальные данные, идемпотентность, срок, повторы, статус и наблюдаемость | Согласовать с async/outbox; сначала проверить реализацию |

## Кандидаты на backend-реализацию

| Ссылка | Результат будущего тикета | Готово, когда | Зависимость/проверка |
|---|---|---|---|
| API-TG-05 | Добавить порт провайдера и адаптер Bot API | Исходящее сообщение использует внешнюю конфигурацию секрета, timeout, обработку ошибок; токен/текст не логируются | Выбран провайдер; проверить библиотеку и совместимость; не добавлять модуль без ADR |
| API-TG-06 | Добавить защищённый webhook/путь привязки | Проверяется webhook secret; nonce одноразовый; чужой пользователь не может привязать аккаунт | Утверждённый контракт и threat model; лимиты злоупотреблений |
| API-TG-07 | Добавить политику пригодности уведомления | Перед отправкой проверяются событие, связь получателя, согласие, язык, срок и подавление | API-TG-02/03; явная политика аудита и тесты |
| API-TG-08 | Доставлять один алерт о новой заявке работодателю | Нейтральный текст и безопасная ссылка только авторизованному участнику с настройкой | Пилот фронтенда, членство компании и утверждённое раскрытие |
| API-TG-09 | Добавить уведомление кандидату о статусе заявки | Только после согласия, из разрешённого события и без раскрытия деталей | Решения по возрасту, защите и тексту; ссылка требует входа |
| API-TG-10 | Доставлять Telegram через долговечный механизм | Асинхронная доставка идемпотентна, ограничена, повторяема и согласована при неопределённом исходе | Проверить включение/работоспособность outbox в целевой среде |
| API-TG-11 | Добавить операторскую видимость ошибок доставки | Метрики и алерты показывают возраст очереди, повторы и терминальные сбои без текста/токена | Владелец observability; граница Cloud Monitoring/Sentry |

## Безопасность, качество и запуск

| Ссылка | Результат будущего тикета | Готово, когда | Зависимость/проверка |
|---|---|---|---|
| API-TG-12 | Сделать threat model привязки и доставки | Рассмотрены поддельный webhook, повтор, раскрытие существования пользователя, чужая привязка, утечка группы, кража токена, flood и отказ провайдера | Проверка безопасности до production |
| API-TG-13 | Проверить согласие и идемпотентность | Тесты для отказа, отсутствующей связи, дубля, устаревшей связи, чужого actor, timeout/429/5xx, постоянного сбоя и безопасных логов | Только fake provider/Testcontainers; live Telegram проверяется отдельно |
| API-TG-14 | Описать настройку секретов и окружений | Токен/secret хранятся через утверждённую систему; есть ротация и отзыв | Настройка владельцем; документация не разрешает конфигурацию |
| API-TG-15 | Проверить пилот end-to-end в non-production | Синтетический пользователь привязался, согласился, получил одно уведомление и отказался; доказательства помечены корректно | Все предусловия; без production-данных и незапрошенных сообщений |

## Предложенный порядок

1. API-TG-01—04: политика и контракты.
2. API-TG-12 и API-TG-13: модель угроз и границы проверок.
3. API-TG-05—07: минимальная безопасная основа.
4. API-TG-08: пилот для работодателя; API-TG-09 — только после решения о коммуникации с кандидатами.
5. API-TG-10, API-TG-11, API-TG-14 и API-TG-15 — до расширения объёма.

Этот backlog не разрешает изменения кода, настройку провайдера, миграции, deployment или операции с секретами. Сопоставьте выбранную API-задачу с [задачей продукта CVNoor](../cvnoor/tasks.md), затем проверьте активные планы обоих репозиториев.
