# Учебный маршрут по интеграциям Telegram

**Для кого:** для разработчика, который хочет разобраться в вариантах интеграции Telegram и изучать примеры репозитория в понятном порядке. **Результат:** вы сможете выбрать механизм интеграции, проследить данные и права доступа, а затем адаптировать подходящий Java-пример, не путая mock с живым подключением.

Начните с шага 1 и двигайтесь по порядку. В каждом уроке есть понятие, маршрут чтения кода, пример для реального проекта и вопрос для самопроверки. Необязательно собирать все примеры. [Английский маршрут](../../learning/README.md) содержит те же шаги.

## Как проходить шаги

1. Сначала прочитайте ментальную модель урока, потом открывайте код.
2. Перейдите по ссылкам «Прочитать и посмотреть»: сначала README, затем один сервис и его тесты.
3. Проследите один синтетический запрос от входа до состояния или исходящего адаптера.
4. Ответьте на контрольный вопрос своими словами. Если не получается — вернитесь к указанным разделам.
5. Откройте заметку issue, если нужны точные детали реализации или границы тестирования.

## Важное различие: демо, проверенный код и живое подключение

Примеры Java реализованы и локально проверяются на синтетических payload, fake-адаптерах и mock HTTP. Это не означает, что репозиторий подключал клиентского бота, Business-аккаунт, CRM tenant, production webhook, пользовательский аккаунт или AI-провайдера. В каждом уроке отмечено, что потребуется для реального развёртывания: конфигурация, постоянное хранилище, identity, проверка приватности и операционные меры.

## Рекомендуемые маршруты

- **Нужны уведомления:** шаги 1 → 2 → 5 (J02/J06/J09).
- **Делаю поддержку или внутренний процесс:** шаги 1 → 2 → 3; добавьте шаг 4 для структурированных форм.
- **Подключаю продажи или CRM:** шаги 1 → 2 → 3 → 5 (J14).
- **Изучаю AI в Telegram:** шаги 1 → 2 → 6 → 7. Не пропускайте согласие и границы источника данных.
- **Нужен доступ Telegram-аккаунта:** шаги 1 → 7. Токен бота — не пользовательская сессия; TDLib — отдельная архитектура клиента.
