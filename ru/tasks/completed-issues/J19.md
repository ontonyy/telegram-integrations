# J19 — Смоделировать оплату и возврат Telegram Stars

[English](../../../tasks/completed-issues/J19.md) · [GitHub issue #19](https://github.com/ontonyy/telegram-integrations/issues/19) · [Учебный урок](../../../learning/09-stars-payments.md)

## Что изменилось

Spring-пример маршрутизирует синтетические `/buy-demo`, `/paysupport`, pre-checkout, successful-payment и `/refund-demo` в `TelegramStarsPaymentService`. Сервис проверяет владельца заказа, валюту `XTR`, ожидаемую сумму, срок действия и состояние checkout. Выдача происходит только после корректного `successful_payment`; charge ID защищают от повторной выдачи, а запрос возврата доступен только покупателю. Подтверждённый возврат не повторяется; неоднозначный результат помечается `REFUND_UNKNOWN` для ручной сверки.

`TelegramStarsGateway` — шов для адаптера. Единственная Spring-реализация — `SimulatedTelegramStarsGateway`, fake в памяти, который не обращается к Telegram и не перемещает Stars. `/buy-demo` только создаёт намерение заказа; приложение не вызывает `sendInvoice`. Unit- и webhook-тесты подают синтетические данные обновлений.

## Проверки и ограничения

Сфокусированные тесты: `./gradlew test --tests example.telegram.TelegramStarsPaymentServiceTest --tests example.telegram.TelegramWebhookControllerTest` из `examples/java-spring/`.

Состояние и идемпотентность update хранятся в ограниченной памяти процесса, теряются при перезапуске и не общие для нескольких экземпляров. Десятисекундный бюджет проверяется по локальным внедрённым часам; тесты не измеряют сетевой срок Telegram. Здесь нет настоящего заказа, выдачи продукта, invoice, платежа, возврата или подключения службы поддержки.

Официальное поведение: [платежи Telegram Stars](https://core.telegram.org/bots/payments-stars), [Bot API `answerPreCheckoutQuery`](https://core.telegram.org/bots/api#answerprecheckoutquery) и [Bot API `refundStarPayment`](https://core.telegram.org/bots/api#refundstarpayment).
