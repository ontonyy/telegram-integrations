# J18 — Общая Mini App для группы с серверной авторизацией и конкурентными изменениями

[English](../../../tasks/completed-issues/J18.md) · [GitHub issue #18](https://github.com/ontonyy/telegram-integrations/issues/18) · [Учебный урок](../../../learning/04-mini-apps.md)

## Что сделано

На страницу Java/Spring Mini App добавлена синтетическая общая доска доступности рядом с персональной формой J07. Для личного вклада используется Telegram ID пользователя из подписанной launch data, `chat_instance` задаёт контекст доски. Общий ответ содержит агрегированные счётчики по слотам и только собственные слоты текущего пользователя, без Telegram ID и индивидуальных вариантов остальных участников.

## Авторизация и изменение состояния

`SharedMiniAppController` проверяет сырую `initData` через `TelegramInitDataValidator`, требует user, `chat_instance` и `chat_type` со значением group/supergroup, затем вызывает `SharedMiniAppAuthorizer`. Настроенная реализация требует точную пару из `TELEGRAM_MINIAPP_SHARED_ALLOWED_MEMBERSHIPS` в виде списка `chat_instance=user_id` через запятую. Пустая конфигурация запрещает запросы. Подписанный контекст не подтверждает членство в группе; allowlist задаёт прикладное правило демо.

`SharedAvailabilityBoardService` хранит вклад каждого подписанного пользователя в доске с ключом `chat_instance`. Изменение применяется, только если отправленная версия совпадает с текущей. Успешная запись увеличивает версию; устаревшее изменение возвращает HTTP 409 и текущее агрегированное состояние, чтобы клиент мог проверить его и повторить действие. Идентичный повтор становится no-op даже со старой ожидаемой версией. Все данные вклада проверяются до изменения доски.

## Применение в реальном проекте

Используйте Mini App по прямой ссылке для совместных сценариев, которым тесно в сообщениях и кнопках. Подписанную личность, контекст Telegram-чата и права приложения учитывайте раздельно. Определите правила регистрации, роли, сроки хранения и раскрытие обработки внутри приложения. Если доска доступна через несколько экземпляров, используйте общее постоянное хранилище и атомарную операцию compare-and-set или транзакцию БД.

## Реализация и ограничения

См. [`SharedMiniAppController`](../../../examples/java-spring/src/main/java/example/telegram/SharedMiniAppController.java), [`ConfiguredSharedMiniAppAuthorizer`](../../../examples/java-spring/src/main/java/example/telegram/ConfiguredSharedMiniAppAuthorizer.java), [`SharedAvailabilityBoardService`](../../../examples/java-spring/src/main/java/example/telegram/SharedAvailabilityBoardService.java), [тесты контроллера](../../../examples/java-spring/src/test/java/example/telegram/SharedMiniAppControllerTest.java) и [тесты сервиса](../../../examples/java-spring/src/test/java/example/telegram/SharedAvailabilityBoardServiceTest.java).

In-memory хранилище содержит максимум 500 досок, 50 участников на доску и 8 слотов на вклад. При перезапуске данные теряются; согласование действует только внутри одной JVM. Allowlist — конфигурация учебного примера, а не каталог реальных участников Telegram-группы. Telegram не предоставляет Mini App историю сообщений группы или право писать от имени пользователя.

**Проверка:** тесты используют синтетические ID пользователей, контекст чата и подписанные launch data. Аккаунт Telegram, публичный URL Mini App, группа и сообщения не использовались. Локальные тесты не подтверждают живой запуск Mini App или конкурентность БД между экземплярами приложения.
