# J03 — Защита Spring webhook и обработка повторов

[English](../../../tasks/completed-issues/J03.md) · [GitHub issue #3](https://github.com/ontonyy/telegram-integrations/issues/3)

## Что сделано

Webhook Telegram проверяет заголовок общего секрета, валидирует update ID, маршрутизирует поддерживаемые формы сообщений/callback и использует точку идемпотентности перед побочными действиями.

## Как это работает

`POST /telegram/webhook` отклоняет незаданный секрет вне явного demo-профиля и сравнивает секреты за постоянное время. `TelegramUpdateRegistry` запоминает обработанные `update_id`; в примере реестр ограничен памятью процесса. Ошибка обработчика возвращает повторяемую service-ошибку, а уже завершённое обновление не повторяет эффект.

Проверка: `./examples/java-spring/gradlew -p examples/java-spring test --tests example.telegram.TelegramWebhookControllerTest`.

## Применение в проекте

Зарегистрируйте HTTPS webhook с Telegram `secret_token`, задайте тот же секрет в secret manager и подпишитесь только на используемые типы обновлений. Ограничьте размер и частоту запросов на edge. Перед запуском нескольких экземпляров замените локальный реестр на общее долговременное хранилище идемпотентности.
