# J20 — Добавить Telegram Login OIDC на Java-сайт

[English](../../../tasks/completed-issues/J20.md) · [GitHub issue #20](https://github.com/ontonyy/telegram-integrations/issues/20) · [Учебный урок](../../../learning/10-telegram-login-oidc.md)

## Что изменилось

В Java/Spring-примере появился необязательный Telegram Login OIDC, реализованный через Spring Security. Используется стандартный authorization-code callback с обязательным PKCE S256; клиентские credentials остаются на сервере, а по умолчанию запрашивается только scope `openid`. `/login-demo/me` возвращает лишь проверенный OIDC subject и не назначает роль приложения. Этот сценарий отделён от HMAC-валидатора Mini App `Telegram.WebApp.initData`.

По умолчанию функция выключена. При включении выполняется OIDC discovery настроенного issuer; по умолчанию используется issuer Telegram. Тесты fake issuer проходят через authorization redirect и callback с синтетическими RSA-ключами и данными. Проверяются PKCE, привязка redirect URI, callback state, ID-token nonce, подпись, issuer, audience, срок действия, минимальный scope и ответ только с subject. В mock discovery намеренно нет UserInfo endpoint — так же устроена документированная граница Telegram.

## Проверки и ограничения

Сфокусированный тест: `./gradlew test --tests example.telegram.TelegramLoginOidcSecurityTest` из `examples/java-spring/`.

Функция использует серверную HTTP-сессию. Хранилище и совместное использование сессий, cookie policy, связывание аккаунтов, авторизация внутри приложения, logout и production-настройка не входят в учебный пример. Тесты используют только loopback mock issuer; регистрация клиента Telegram, credentials, профиль пользователя и live-вход не использовались. Необязательные scopes `profile`, `phone` и bot access по умолчанию не запрашиваются.

Официальное поведение: [Telegram Login OIDC](https://core.telegram.org/bots/telegram-login), [Spring Security OAuth2 Login](https://docs.spring.io/spring-security/reference/servlet/oauth2/login/) и [конфигурация OAuth2-клиента Spring Boot](https://docs.spring.io/spring-boot/reference/security/oauth2.html).
