# J21 — Проверка восстановления загрузки J10 между отдельными JVM

[English version](../../../tasks/completed-issues/J21.md) · [GitHub issue #21](https://github.com/ontonyy/telegram-integrations/issues/21)

## Что сделано

Тест `FileIntakeServiceTest.preservesAndRecoversWorkspaceLeasedByAnotherJvm` запускает отдельные JVM-процессы, которые удерживают блокировку lease в общем временном каталоге. Он проверяет, что intake сохраняет синтетический частичный файл активного процесса, следующий intake удаляет его каталог после принудительного завершения процесса, а очистка сохраняет каталог второго активного процесса.

Запустите тест из `examples/java-spring`:

```bash
./gradlew test --tests example.telegram.FileIntakeServiceTest.preservesAndRecoversWorkspaceLeasedByAnotherJvm
```

## Проверка и ограничения

Тест использует только синтетический текст и локальные процессы; он не обращается к Telegram и не использует credentials. Успешный результат подтверждает поведение только той файловой системы, на которой выполнен тест. Он не доказывает надёжность Java `FileLock` для NFS, container volumes или других файловых систем развёртывания. Перед использованием очистки в общей среде проверьте именно целевую файловую систему.
