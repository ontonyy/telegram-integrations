# Задача 1: завершить набор примеров Telegram на Java

## Статус

**Запланированные примеры без реальных credentials реализованы:** `examples/java-spring/` содержит запускаемые сценарии на Java 25/Spring Boot: dry-run webhook Bot API, Mini App с проверкой владельца заявки, приём текстовых файлов с согласием пользователя и необязательный AI-сценарий для запроса из личного чата с подтверждением каждого вопроса. Отдельный [пример TDLib Java для пользовательского аккаунта](../../examples/tdlib-java/README.md) не подключён к обычному запуску Spring и требует отдельной ручной настройки native/JNI. При этой работе реальные credentials и аккаунт Telegram не использовались. Инструкции: [README Spring-примера](../../examples/java-spring/README.md) и [README TDLib](../../examples/tdlib-java/README.md).

[J05](https://github.com/ontonyy/telegram-integrations/issues/5) реализована как Business support adapter с заглушками в [примере Java/Spring](../../examples/java-spring/README.md#telegram-business-поддержка-и-передача-оператору). Обрабатываются обновления подключения и новые/изменённые/удалённые сообщения; создаются минимальные метаданные in-memory без текста переписки; тесты проверяют передачу оператору и ограничения ответа от имени бизнеса. Business-аккаунт, диалог клиента, helpdesk и реальные отправки не использовались.

Сценарий FAQ с AI из [J11](https://github.com/ontonyy/telegram-integrations/issues/11) реализован с раскрытием обработки, отзывным согласием, отдельным подтверждением каждого запроса, только личным чатом, отменой запроса и подменяемым Claude-клиентом. Передаётся только текст, который пользователь отправил напрямую; история чата, группы, файлы, Business-сообщения и данные других пользователей в AI не передаются. Заглушки не подтверждают соответствие условиям Telegram или работу живого провайдера.

Ограниченный приём файла из [J10](https://github.com/ontonyy/telegram-integrations/issues/10) реализован. Он требует отдельного раскрытия цели и согласия в личном чате, использует временное хранилище с правами владельца и удаляет файл после подсчёта локальной статистики. Содержимое файла не отправляется AI.

[J14](https://github.com/ontonyy/telegram-integrations/issues/14) реализована как сбор заявки с mock-backed HubSpot интеграцией в [примере Java/Spring](../../examples/java-spring/README.md#сбор-заявки-на-продажу-с-явным-согласием-и-hubspot). Бот сначала раскрывает цель и получателей, затем запрашивает отдельное согласие в личном чате; в CRM передаются только введённые клиентом поля, контакт обновляется по email, назначается настроенный HubSpot owner, а менеджер получает уведомление только с CRM reference. Сделка и маркетинговая подписка не создаются; Telegram-профиль и история не копируются. Unit-тесты используют fake CRM и Telegram adapters; живые записи в CRM и отправки не выполнялись. Согласие и подавление повторных уведомлений — только in-memory состояние демо.

## Пример TDLib Java для пользовательского аккаунта

В [примере TDLib](../../examples/tdlib-java/README.md) официальный JNI adapter находится в отдельном source set, вне обычного старта Spring Boot. Тесты с fake port проверяют разрешённые действия по состояниям авторизации и не требуют credentials. Необязательный live adapter использует явный ввод номера/кода/пароля; единственное действие с данными аккаунта — по команде показать до десяти названий чатов основного списка. Тела сообщений не загружаются, история не индексируется, AI не вызывается. README описывает защиту локальной БД и ключа, локальный logout, отзыв сессии в Telegram и полное удаление. Реальные credentials, native-сборка, вход в аккаунт и чтение чатов не выполнялись.

## Требования

- Код, идентификаторы и заметки для агентов писать на английском; поддерживать читательскую русскую версию.
- Не коммитить токен бота, API ID/hash, телефон, код входа, TDLib-сеанс/БД, сообщения пользователя и секреты провайдера.
- Получать секреты из переменных окружения или secret manager. Не добавлять заполненный `.env`.
- Проверять права и данные на сервере; действия ограничивать явным списком.
- При локальной разработке не отправлять реальные сообщения Telegram и не подключать аккаунт без отдельного запроса.
- До AI-обработки данных Telegram повторно проверить условия Telegram, согласие для конкретного контекста, хранение у провайдера и требования приватности. Для J11 условия Telegram API, лицензия на контент, условия Bot Developer и сведения о хранении Anthropic API проверены 2026-11-15; перед запуском проверку нужно повторить.
- Объяснить границы локальных и смоделированных примеров: они не подтверждают работу живой интеграции.

## Критерии завершения

- Добавить отдельные инструкции для TDLib и приёма файлов: требования, запуск, удаление и область доступных данных. **Готово:** [README TDLib Java](../../examples/tdlib-java/README.md) и [README Java/Spring](../../examples/java-spring/README.md).
- Сохранить возможность компиляции существующего примера без учётных данных.
- Перед коммитом проверить отслеживаемые файлы на секреты и выполнить `git diff --check`.
