# Задача 1: завершить набор примеров Telegram на Java

## Статус

**Реализована частично:** в `examples/java-spring/` добавлены запускаемые примеры на Java 25/Spring Boot: dry-run webhook Bot API, Mini App с проверкой владельца заявки, приём текстовых файлов с согласием пользователя и необязательный AI-сценарий для вопроса из личного чата с подтверждением каждого запроса. AI-пример обрабатывает только текст, явно отправленный боту; историю групп и сообщения Telegram Business он не читает. Отправка сообщений и скачивание файлов выключены по умолчанию. Инструкция: [README примера](../../examples/java-spring/README.md).

Сценарий FAQ с AI из [J11](https://github.com/ontonyy/telegram-integrations/issues/11) реализован с раскрытием обработки, отзывным согласием, отдельным подтверждением каждого запроса, только личным чатом, отменой запроса и подменяемым Claude-клиентом. Передаётся только текст, который пользователь отправил напрямую; история чата, группы, файлы, Business-сообщения и данные других пользователей в AI не передаются. Заглушки не подтверждают соответствие условиям Telegram или работу живого провайдера.

Ограниченный приём файла из [J10](https://github.com/ontonyy/telegram-integrations/issues/10) реализован. Он требует отдельного раскрытия цели и согласия в личном чате, использует временное хранилище с правами владельца и удаляет файл после подсчёта локальной статистики. Содержимое файла не отправляется AI.

## Оставшиеся примеры

1. **TDLib для Java** — инициализировать официальный JNI-клиент и показать этапы авторизации через явное действие пользователя. Показывать только чаты, доступные вошедшему аккаунту. Хранить сеанс вне репозитория; добавить отзыв доступа и удаление сеанса. Не добавлять скрытый сбор и действия без команды пользователя.

## Требования

- Код, идентификаторы и заметки для агентов писать на английском; поддерживать читательскую русскую версию.
- Не коммитить токен бота, API ID/hash, телефон, код входа, TDLib-сеанс/БД, сообщения пользователя и секреты провайдера.
- Получать секреты из переменных окружения или secret manager. Не добавлять заполненный `.env`.
- Проверять права и данные на сервере; действия ограничивать явным списком.
- При локальной разработке не отправлять реальные сообщения Telegram и не подключать аккаунт без отдельного запроса.
- До AI-обработки данных Telegram повторно проверить условия Telegram, согласие для конкретного контекста, хранение у провайдера и требования приватности. Для J11 условия Telegram API, лицензия на контент, условия Bot Developer и сведения о хранении Anthropic API проверены 2026-11-15; перед запуском проверку нужно повторить.
- Объяснить границы локальных и смоделированных примеров: они не подтверждают работу живой интеграции.

## Критерии завершения

- Добавить отдельные инструкции для TDLib и приёма файлов: требования, запуск, удаление и область доступных данных.
- Сохранить возможность компиляции существующего примера без учётных данных.
- Перед коммитом проверить отслеживаемые файлы на секреты и выполнить `git diff --check`.
