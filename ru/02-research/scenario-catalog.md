# Каталог практических сценариев

**Проверено:** 15 ноября 2026 года. Сложность: низкая — настройка; средняя — интеграция/сервер; высокая — собственный клиент или чувствительный процесс между системами.

| Пилот | Пользователь и интерфейс | Системы и поток данных | Механизм/отправитель | AI, стоимость и сложность |
|---|---|---|---|---|
| Поддержка | Клиент пишет; оператор отвечает в helpdesk | Update Telegram → inbox → назначение → ответ | Bot API-бот или Business-бот при поддержке продукта | AI не нужен; места/хостинг helpdesk; низкая–средняя |
| Сбор заявки на продажу | Клиент раскрывает поля и даёт согласие; менеджер получает ссылку на CRM-запись | Личный чат Bot API → upsert контакта HubSpot по email → владелец CRM → уведомление менеджеру только с reference | Bot API + HubSpot CRM API; пишутся поля, которые ввёл пользователь, без Telegram ID/профиля | AI не нужен; нужны доступ к HubSpot и настройка владельца; средняя. Java-пример не создаёт сделку и не включает маркетинговую подписку: [сценарий HubSpot](../../examples/java-spring/README.md#consent-gated-sales-lead-capture-with-hubspot). |
| Запись на встречу | Клиент выбирает время и получает напоминание | Кнопки или Mini App → календарь → подтверждение | Bot API + Mini App для сложного выбора | AI не нужен; возможна плата сервиса записи; средняя |
| Цифровая покупка | Клиент оплачивает цифровой план/контент | Счёт Stars → событие оплаты → право доступа | Bot API, бот отправляет статус | AI не нужен; экономика Stars и поддержка; средняя |
| Статус физического заказа | Клиент указывает заказ и проверяет доставку | Mini App → заказ/склад/платёж → сообщение статуса | Bot API + Mini App + платёжный провайдер | AI не нужен; комиссия провайдера и сервер; средняя |
| Дайджест руководителю | Менеджер получает метрики и ссылки | Плановый CRM/ERP запрос → агрегация → бот | Bot API | AI может сформулировать сводку, не обязателен; низкая |
| Мобильное согласование | Менеджер нажимает «да/нет» | Callback → проверка прав/политики → аудит → изменение системы | Inline-кнопка Bot API + backend | AI не нужен и не должен разрешать действие; средняя |
| Внутренняя заявка и согласование | Сотрудник создаёт приватную заявку и смотрит статус; менеджер проверяет и подтверждает approve/reject с телефона | Личный чат Bot API → прикладной справочник ролей → ограниченное состояние заявки → callback в чате согласования → статус/аудит | Bot API; server-side связь employee/manager; права администратора группы не считаются авторизацией | AI не нужен. Нужны хостинг; до production — постоянное хранилище и SSO; средняя. См. [Java/Spring пример](../../examples/java-spring/README.md#private-employee-request-and-manager-approval). |
| Публикация в канале | Подписчик видит пост или отвечает на опрос | Редакционный процесс → канал → CTA → CRM | Bot API, канал/группа | AI может подготовить текст; публикацию проверяет человек; низкая–средняя |
| Черновик поддержки с AI | Оператор видит предложение и редактирует | Helpdesk диалог + разрешённая база → модель → черновик → отправка оператором | AI helpdesk или внешний провайдер, канал не меняется | Стоимость модели и согласия/приватность; средняя |
| Инженерный алерт | Дежурный видит сборку, алерт и runbook | GitHub/Grafana → alert router → группа Telegram | Bot API или Grafana contact point | AI не нужен, логи очищать; низкая |
| Инцидент → обновление клиентов | Менеджер видит влияние; обращения получают статус | Мониторинг → сервис инцидентов → внутренний алерт/согласование → CRM/helpdesk | Bot API + защищённые API | AI может помочь со сводкой; публикацию подтверждает человек; средняя/высокая |
| Поиск личных чатов | Пользователь спрашивает о рабочем обсуждении | TDLib-сеанс → контролируемый поиск → результаты | TDLib, пользовательский аккаунт | AI только после проверки условий/согласия; высокий риск/сложность |
| Собственная рабочая панель | Менеджер видит чаты, задачи, сборки, отчёты | Telegram + CRM + GitHub/Jira API → своё веб-приложение | Обычно webhook Bot API; TDLib только при реальной необходимости | AI необязателен; дорогая разработка и права доступа; высокая |

Перед запуском уточните, что прямо обещано Telegram/поставщиком, а что является проектным предложением. Смотрите отдельные материалы и [карту возможностей](capability-map.md).

## Шесть небольших пилотов

1. **Клиент — заявка на встречу:** меню бота с тремя вариантами услуг и передача в календарь/API. Подключить бот и расписание. Небольшой код или Make/n8n; без AI.
2. **Клиент — статус заказа:** бот просит номер заказа, backend проверяет его и отдаёт безопасный статус. Подключить API заказов. Небольшой Java endpoint; без AI.
3. **Менеджер — новый лид:** событие CRM отправляет краткий текст и ссылку менеджеру. CRM automation и бот. No-code или небольшая настройка; без AI.
4. **Менеджер — дневная сводка:** агрегировать открытые/просроченные тикеты и инциденты. Подключить helpdesk и Grafana/CRM. Небольшой плановый процесс; AI не нужен для первого варианта.
5. **Руководитель команды — IT-заявка:** бот собирает категорию и описание, создаёт тикет и возвращает номер. Bot API и helpdesk. No-code или небольшой сервис; AI необязателен.
6. **Разработчик — CI/Grafana:** сбой сборки или alert отправляет краткий текст и ссылку в дежурную группу. GitHub Actions/Grafana и бот. Несколько настроек; без AI.

Эти пилоты начинаются с предсказуемой автоматизации. Перед AI или анализом истории диалогов проверьте права и согласия в разделе [AI и данные Telegram](ai-and-data.md).
