# AI и доступ к данным Telegram

**Проверено:** 14 ноября 2026 года.

## Важное ограничение правил

Условия лицензирования контента Telegram запрещают скрейпинг, индексирование и агрегацию данных, а также использование для разработки, улучшения, проверки, сравнения или развёртывания AI/ML, кроме случаев явного, информированного, утвердительного и продолжающегося согласия всех затронутых пользователей для конкретного содержимого и чата/контекста. Условия разработчиков ботов отдельно запрещают сбор сверх необходимого и сбор для больших наборов данных, ML-моделей и AI-продуктов, включая скрейпинг открытых групп и каналов. Они допускают обработку данных, добровольно отправленных пользователем непосредственно боту, если цель раскрыта и есть индивидуальное явное, активное и отзывное согласие. Для Telegram Business также запрещена передача сообщений/файлов третьим сторонам, включая внешние API, без авторизации пользователя. Одного поля согласия недостаточно, чтобы считать массовую индексацию или отправку внешней модели разрешённой; перед реализацией проверьте актуальные условия и требования по персональным данным.

Перед отправкой диалога внешнему AI-провайдеру проверьте условия Telegram, согласие участников, обработку данных, срок хранения, регион и удаление. По умолчанию не передавайте содержимое Telegram в AI. Минимизируйте и редактируйте данные, предоставьте отказ и перевод человеку.

## Что видят разные интеграции

| Интеграция | Доступные данные | Чего нельзя предполагать |
|---|---|---|
| Обычный бот | Личные сообщения, отправленные боту; сообщения групп в рамках privacy/admin режима; обновления канала, где бот состоит/имеет права | Чтение всех личных диалогов, автоматический доступ к закрытым группам или получение произвольной старой истории |
| Подключённый Business-бот | Выбранные личные получатели и сообщения в пределах выданных прав; соединение можно приостановить/отключить | Доступ ко всем чатам, контактам и неограниченной истории аккаунта; права задаются явно |
| Клиент TDLib | Данные аккаунта, вошедшего пользователя, которые доступны через Telegram client API | Доступ к чатам, невидимым пользователю, и обход ограничений API/приватности |
| Коннектор поставщика | Документированные триггеры/действия и настроенная область доступа | Доступ к истории всех чатов только потому, что написано «интеграция Telegram» |
| MCP-сервер | Инструменты, которые сервер явно предоставил и пользователь разрешил | Полное чтение Telegram; MCP сам не выдаёт идентичность и права |

### Пример MCP, проверенный по исходникам: `telegram-mcp-readonly`

[README проекта](https://github.com/mshykhov/telegram-mcp-readonly) описывает MCP-сервер на Telethon user session для поиска по чатам аккаунта, чтения истории и загрузки вложений. В изученном `runtime.py` по умолчанию используется строгий именованный read-only allowlist; setup записывает этот режим, а загрузчик ограничен заданной папкой. Это ограничение на уровне приложения, но не право аккаунта Telegram: в тех же исходниках есть изменяющие инструменты и более широкие режимы, а пользовательская сессия остаётся полноценной клиентской сессией Telegram. При компрометации или изменении настройки сервер может выйти за read-only интерфейс. Храните сессию локально, изолируйте её файлы/ключ, фиксируйте и проверяйте commit, отключите широкие режимы и не путайте техническую доступность с разрешением обрабатывать содержимое.

Такая же разница есть у других MCP/TDLib readers. В [обзоре реализаций](implementation-landscape.md) классифицированы проекты и указаны изученные файлы. MCP-проекты здесь не устанавливались, не авторизовались и не запускались.

## Claude, Codex и текущее окружение

Нельзя предполагать, что Claude или Codex имеют встроенный доступ к Telegram. MCP — протокол: отдельный сервер может предоставить выбранные функции только после установки, настройки, авторизации и выдачи области доступа. Claude Code документирует локальные stdio и удалённые HTTP/SSE MCP-серверы. Responses API OpenAI поддерживает удалённые MCP и контроль инструментов/подтверждений. Codex CLI/SDK позволяет запускать ограниченные и программные задачи кодирования, но не подключает Telegram сам по себе. Обычно нужен отдельный сервис, который получает updates, применяет проверки согласия и политики, выбирает разрешённые данные, вызывает API модели и решает, вернуть черновик или отправить ответ.

Проверка **14 ноября 2026 года**: Codex CLI и Claude Code CLI установлены, но в их списках MCP нет Telegram. Подключённые инструменты приложений не содержат Telegram-коннектора; Codex Document Control сообщил, что сессия документа не подключена. Это снимок данного окружения, не утверждение о доступности всех продуктов. Перед реализацией проверьте `codex mcp list`, `claude mcp list` и настройки подключённых плагинов.

### Интерфейс AI и источник данных

- **Telegram как интерфейс AI:** пользователь напрямую отправляет вопрос боту; после уведомления и активного отзываемого согласия модели можно передать только отправленный вопрос. Для базовых ответов не нужна история группы.
- **Telegram как источник AI:** агент получает историю через коннектор или TDLib. Это отдельный рискованный сценарий. Bot API не даёт произвольную историю группы; TDLib ограничена доступными вошедшему аккаунту данными и условиями Telegram. Не создавайте широкую индексацию по умолчанию.
- **Черновик менеджера:** оператор выбирает разрешённое обращение и запрашивает неподтверждённый черновик. Передача Business-контента во внешний API требует авторизации пользователя.
- **Файлы:** бот может получить отправленный ему файл в пределах ограничений Bot API. Сервис может извлечь текст с заявленной целью; загруженный контент нельзя исполнять. Проверьте хранение/удаление у провайдера и связывайте ID его файлов с отправителем на сервере.

**Подтверждено:** условия и ограничения API из источников ниже. **Предложено:** схема сервиса, цитирования и черновика; нужна проверка приватности, согласия и хранения.

## Более безопасные AI-сценарии

1. **Человек сам спрашивает бота:** сообщить, что вопрос будет обработан моделью, получить нужное активное согласие, отправить вопрос и выбранные статьи базы знаний, предусмотреть отказ/оператора.
2. **Черновик ответа оператору:** уполномоченный оператор выбирает тикет и просит черновик; модели передаются только этот тикет и разрешённая база знаний, ответ возвращается как черновик без отправки. Передача диалога модели должна быть разрешена.
3. **Сводка показателей:** отправить агрегаты CRM/мониторинга, а не текст диалогов.
4. **Поиск по корпоративной базе:** индексировать только данные, которыми организация вправе пользоваться; исключить историю Telegram, пока не определена узкая законная модель согласия.

AI может работать в Chatwoot Captain/подключённом провайдере, Intercom Fin, внешнем API или собственной модели. В каждом случае укажите, какие сообщения, файлы, CRM-поля и документы передаются наружу. AI полезен для неоднозначного текста, поиска, сводок и черновиков; фиксированные правила маршрутизации и напоминаний проще и дешевле делать обычной автоматизацией.
