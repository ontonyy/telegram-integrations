# Группы, темы и совместные Mini Apps в Telegram

**Проверено:** 14 ноября 2026 года. Bot API 10.4.

## Что видит бот

Обычного бота можно добавить в группу. Согласно FAQ Bot API, бот получает служебные сообщения; в группе администратор-бот или бот с отключённым privacy mode получает все сообщения, кроме сообщений других ботов. При включённом по умолчанию privacy mode бот получает команды, адресованные ему, некоторые общие команды, сообщения через бота и ответы, направленные боту. Bot API не предоставляет произвольную старую историю группы. Бот-участник канала получает доступные ему обновления канала; публикация и модерация требуют соответствующих прав.

Темы форума — отдельные беседы внутри супергруппы. Бот может ответить в тему, передав `message_thread_id`; для создания, изменения и удаления тем требуются права управления темами. Разделение поддержки, релизов и инцидентов по темам упрощает работу с телефона.

## Как выбрать взаимодействие

| Задача | Возможность Telegram | Граница данных |
|---|---|---|
| Явное действие в группе | `/task`, адресованная команда, ответ, кнопка | Бот получает адресованное обновление и контекст ответа, если он доступен; не всю историю |
| Голосование за время | Опрос Bot API или кнопки | Варианты и голоса, но не история личных чатов |
| Совместный заказ или выбор доступности | Mini App по прямой ссылке | `chat_type`/`chat_instance` позволяют создать общую область на сервере; приложение не читает сообщения и не пишет от имени пользователя |
| Длительный командный процесс | Тема форума и уведомления бота | Только сообщения, доступные по настройкам privacy mode и правам |
| Краткое содержание обсуждения | Пользователь явно отправляет текст или отвечает на сообщение | Ограничьте запрос переданным текстом; раскройте обработку AI и проверьте условия Telegram |

Не отключайте privacy mode, если функции не нужны фоновые обновления группы. Если отключаете, объясните цель участникам, ограничьте хранение данных и соблюдайте условия Bot Developer Terms. Выбор получателей подключённого Business-бота описан для личных чатов; это не подтверждает доступ такого бота ко всем группам аккаунта.

## Примеры процессов

### Создать задачу из сообщения после явного действия

1. Участник отвечает `/task` на сообщение или нажимает кнопку бота.
2. Бот получает команду и контекст исходного сообщения, если он передан.
3. Backend проверяет группу, разрешённую тему и роль пользователя.
4. Backend создаёт задачу в Jira/CRM и сохраняет ссылку на исходное сообщение, если Telegram предоставляет подходящую ссылку.
5. Бот отправляет короткое подтверждение в эту тему. AI по умолчанию не получает текст.

### Совместно выбрать время

Для быстрого голосования используйте обычный опрос. Mini App по прямой ссылке подходит, если нужны правила доступности, часовые пояса, итоговое бронирование или совместное редактирование. Храните общее состояние по `chat_instance` и идентификатору записи приложения; это идентификатор контекста, а не список участников и не средство авторизации.

### Запросить краткое содержание

При включённом privacy mode попросите пользователя явно ответить боту с текстом или вызвать команду на доступном сообщении. Не собирайте незаметно весь поток группы. Человек должен иметь возможность проверить источники и подтвердить действие, основанное на выжимке.
