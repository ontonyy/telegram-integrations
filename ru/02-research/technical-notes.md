# Технические заметки: Bot API, Business, Mini Apps, TDLib и Java

**Проверено:** 14 ноября 2026 года. На дату проверки на официальной странице был указан Bot API 10.3. Перед реализацией сверяйте текущую версию и методы.

## Bot API

HTTPS API для серверной логики ботов. Получать события можно через long polling (`getUpdates`) или webhook; для одного бота нельзя одновременно использовать оба способа. Webhook требует публичный HTTPS и проверку заданного secret token в заголовке. Telegram хранит обновления ограниченное время (FAQ указывает до 24 часов). Bot API поддерживает сообщения, файлы, inline-клавиатуры, callback, опросы, платежи и действия в каналах/группах, где бот состоит и имеет права. Видимость групп зависит от privacy mode. Бот не может первым написать произвольному пользователю.

Варианты для Java: стандартный `java.net.http.HttpClient` для исходящих вызовов; TelegramBots или Pengrad для обработки обновлений и типов запросов; Spring Boot webhook для сервиса. Зафиксируйте версию библиотеки и проверьте покрытие текущего API.

## Telegram Business

Владелец Business подключает бота, выбирает адресатов и выдаёт права. Bot API предоставляет поля business connection/update и идентификаторы соединения; отправка/редактирование зависят от разрешённых прав и контекста адресата/сообщения. Право ответа связано с недавним входящим сообщением (в документации — окно 24 часа). Поставщик должен явно описывать этот режим; обычный коннектор с «bot token» может поддерживать только разговоры с ботом. В текущей документации указана модель с одним подключённым Business-ботом на аккаунт. Функции Business и Premium зависят от рынка; документация указывает, что подключённые боты доступны и без Premium.

## Mini Apps

Mini App — веб-приложение, запускаемое из бота. Кнопок чата достаточно для простых процессов, Mini App нужен для насыщенного интерфейса. Передавайте `initData` серверу и проверяйте подпись; не доверяйте `initDataUnsafe` или ID пользователя из браузера для авторизации. Backend — источник истины для цены, роли и права на действие. Java подходит для API и бизнес-логики, интерфейс делается веб-технологиями.

## TDLib для Java

TDLib — кроссплатформенная клиентская библиотека Telegram. Java API работает через JNI: TDLib нужно собрать с JNI (официальная инструкция использует `-DTD_ENABLE_JNI=ON`) и доставить совместимые native-библиотеки. API асинхронный и скрывает часть протокола/сети. Приложение всё равно реализует авторизацию, цикл обновлений, интерфейс чатов, защиту локальной базы/сеанса, восстановление и удаление. Сеанс пользователя даёт доступ к данным его аккаунта, доступным Telegram-клиенту. Защитите ключ шифрования и локальную БД, ограничьте доступ операторов, опишите отзыв авторизации и удаление.

Для поиска по рабочим чатам или собственного клиента сначала проверьте, нельзя ли решить задачу ботом. TDLib резко увеличивает нагрузку по безопасности и эксплуатации и не является просто «расширенным токеном бота».

## Учётные данные и эксплуатация

- Bot token и webhook secret: secret manager/переменные окружения, никогда не Git.
- `api_id`/`api_hash`, телефон, код входа и TDLib-сеанс: закрытые секреты и данные, не коммитьте даже тестовый сеанс.
- Проверяйте подпись Mini App на сервере; не пишите полное launch data в логи.
- Для webhook: сверяйте secret header, ограничьте размер запроса, делайте callback идемпотентным, быстро подтверждайте событие и выносите долгую работу в очередь.
- Для файлов: ограничьте размер/тип, проверяйте по необходимости, задайте срок хранения и удаляйте временные копии.
