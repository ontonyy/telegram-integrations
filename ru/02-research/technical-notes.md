# Технические заметки: Bot API, Business, Mini Apps, TDLib и Java

**Проверено:** 14 ноября 2026 года. В официальной истории версий указан Bot API **10.4** от 9 ноября 2026 года. Перед реализацией сверяйте актуальные методы; 10.4 добавила HTML widgets и эфемерные ответы на callback, а widgets пока ограничены личными чатами в production.

## Bot API

HTTPS API для серверной логики ботов. Получать события можно через long polling (`getUpdates`) или webhook; для одного бота нельзя одновременно использовать оба способа. Webhook требует публичный HTTPS и проверку заданного secret token в заголовке. Telegram хранит обновления ограниченное время (FAQ указывает до 24 часов). Bot API поддерживает сообщения, файлы, inline-клавиатуры, callback, опросы, платежи и действия в каналах/группах, где бот состоит и имеет права. Видимость групп зависит от privacy mode. Бот не может первым написать произвольному пользователю.

Варианты для Java: стандартный `java.net.http.HttpClient` для исходящих вызовов; TelegramBots или Pengrad для обработки обновлений и типов запросов; Spring Boot webhook для сервиса. Зафиксируйте версию библиотеки и проверьте покрытие текущего API.

## Telegram Business

Владелец Business подключает бота, выбирает адресатов и выдаёт права. Telegram определяет область получателей как **личные чаты**: существующие/новые, контакты/не контакты, выбранные пользователи и исключения. Отдельный чат можно приостановить или отключить. Bot API предоставляет business updates и ID соединения; действия зависят от прав и контекста сообщения. В документированном сценарии ответа действует окно 24 часа после последнего входящего сообщения. На аккаунт подключается один Business-бот; подключение не требует Premium. Не делайте из этой функции вывод о группах/каналах. Условия для разработчиков запрещают передавать сообщения/файлы Business сторонним API без авторизации пользователя. Поставщик должен явно подтверждать Business-режим: обычный bot token этого не доказывает.

## Mini Apps

Mini App — веб-приложение, запускаемое из профиля бота, кнопки, меню, inline-режима, прямой ссылки или меню вложений (с ограничениями доступности). Прямая ссылка может открываться из группы и передавать `chat_type` и `chat_instance` для общего серверного контекста. Mini App не видит сообщения и не отправляет от имени пользователя; для публикации результата пользователь выбирает inline-вариант. Передавайте сырые `initData` серверу и проверяйте HMAC; не доверяйте `initDataUnsafe`. Проверяйте свежесть `auth_date`. Telegram ID не заменяет авторизацию в самом продукте. Java подходит для API и бизнес-логики, интерфейс делается веб-технологиями.

## TDLib для Java

TDLib — кроссплатформенная клиентская библиотека Telegram. Java API работает через JNI: TDLib нужно собрать с JNI (официальная инструкция использует `-DTD_ENABLE_JNI=ON`) и доставить совместимые native-библиотеки. API асинхронный и скрывает часть протокола/сети. Приложение всё равно реализует авторизацию, цикл обновлений, интерфейс чатов, защиту локальной базы/сеанса, восстановление и удаление. Сеанс пользователя даёт доступ к данным его аккаунта, доступным Telegram-клиенту. Защитите ключ шифрования и локальную БД, ограничьте доступ операторов, опишите отзыв авторизации и удаление.

Для поиска по рабочим чатам или собственного клиента сначала проверьте, нельзя ли решить задачу ботом. TDLib резко увеличивает нагрузку по безопасности и эксплуатации и не является просто «расширенным токеном бота».

## Учётные данные и эксплуатация

- Bot token и webhook secret: secret manager/переменные окружения, никогда не Git.
- `api_id`/`api_hash`, телефон, код входа и TDLib-сеанс: закрытые секреты и данные, не коммитьте даже тестовый сеанс.
- Проверяйте подпись Mini App на сервере; не пишите полное launch data в логи.
- Для webhook: сверяйте secret header, ограничьте размер запроса, делайте callback идемпотентным, быстро подтверждайте событие и выносите долгую работу в очередь.
- Для файлов: ограничьте размер/тип, проверяйте по необходимости, задайте срок хранения и удаляйте временные копии.

## Группы, темы и privacy mode

По FAQ Bot API бот получает личные сообщения, отправленные ему, служебные сообщения и сообщения каналов, где он состоит. В группе администратор-бот или бот с отключённым privacy mode получает все сообщения, кроме сообщений других ботов. При включённом по умолчанию privacy mode бот видит команды, адресованные ему, некоторые общие команды, сообщения через него и ответы на него. Это не API истории. Для создания задач/сводок используйте явную команду, ответ или кнопку. Форум — супергруппа с темами; для ответа в тему передавайте `message_thread_id`. Управлять темами можно с правом `manage_topics`.

## Платежи

Для цифровых товаров и услуг, продаваемых через ботов или Mini Apps, условия Bot Developer Terms требуют Telegram Stars. Для физических товаров и услуг Bot Platform позволяет подключать сторонних платёжных провайдеров с учётом их доступности и условий. Перед запуском проверьте правила магазинов приложений.
