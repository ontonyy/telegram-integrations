## Prioritized bets

1. **Shared group Mini App.** Key bet: developers can safely model shared state by separating signed actor identity, chat context, app authorization, and concurrent writes. Cheapest validation is the mock-only pilot in J18. Nearest existing alternatives in this repository are J04 group callbacks and J07 owner-scoped Mini App records; neither demonstrates shared versioned state.
2. **Stars lifecycle simulation.** Key bet: a deterministic state-machine lesson is useful enough to justify payment-specific complexity. Cheapest validation is a fake-transport exercise with replay, failed delivery and refund transitions. Nearest alternatives are payment flow notes in `02-research/customer-services.md` and the generic durable outbox in J16; neither models Stars payment authority and refund lifecycle.
3. **Telegram Login OIDC.** Key bet: readers need the normal website login protocol as a separate example from Mini App initData. Cheapest validation is a local mock issuer and claim-validation tests. The nearest existing repository example is J07, which validates Mini App launch data but is not OIDC.

## Policy and production boundaries

Telegram's Bot Developer Terms limit data collection to what is essential and allow direct voluntary submissions only with clear disclosure and each user's explicit, active, revocable consent. Content Licensing Terms prohibit using platform data for AI/ML except a narrow, context-specific exception requiring explicit, informed, continued consent from all relevant users. A participant's consent does not authorize processing everyone else's group or Business messages. See [Bot Developer Terms](https://telegram.org/tos/bot-developers) and [Content Licensing Terms](https://telegram.org/tos/content-licensing).

Current official docs describe direct-link Mini Apps as receiving `chat_type`/`chat_instance` for shared context, while having no access to read group messages or send as the user. Telegram Login documents OIDC Authorization Code Flow with PKCE. Bot API 10.4 (2026-11-09) adds ephemeral callback replies and HTML widgets; widgets are currently production-limited to private chats and are protected from forwarding. Check those restrictions again before an implementation. Sources: [Mini Apps](https://core.telegram.org/bots/webapps), [Telegram Login](https://core.telegram.org/bots/telegram-login), [Bot API](https://core.telegram.org/bots/api).

No live provider/account setup or verification was performed for this review.
