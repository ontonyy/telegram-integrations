# Task 1: Complete the Java Telegram example set

## Status

**Partially implemented:** `examples/java-spring/` now contains a runnable Java 25/Spring Boot sample for a dry-run Bot API webhook, server-side Mini App `initData` validation, and an optional Claude Messages API call gated by private-chat consent. The AI example processes only text explicitly submitted to the bot; it does not read group history or Telegram Business chats. Outbound Telegram sends are disabled by default. See its [README](../examples/java-spring/README.md).

## Remaining examples

1. **TDLib Java client flow** — initialize the official JNI client and demonstrate its authorization states using an explicit user-driven flow. Show only chats available to that signed-in account. Keep session data outside the repository and include clear revoke/delete steps. Do not add hidden collection or unattended user actions.
2. **Bounded user-submitted file intake** — receive a Bot API document, enforce content/size limits, download to a temporary directory, process safely without executing content, and clean up. Do not connect it to AI by default.

## Requirements

- Keep code, identifiers and agent-facing notes in English; maintain a Russian reader copy.
- No real bot token, API ID/hash, phone, login code, TDLib session/database, user message, or provider secret in tracked files.
- Read secrets from environment variables or a secret manager. No populated `.env` files.
- Validate authorization and input server-side; keep actions allowlisted.
- Do not send real Telegram messages or connect an account during local development without a separate request.
- Before any AI workflow on Telegram-origin data, review current Telegram terms, scoped consent, provider retention and privacy requirements.
- Explain local/mock boundaries; they do not prove a live integration.

## Completion criteria

- Add independent instructions for TDLib and file intake: prerequisites, run, cleanup and data scope.
- Keep the existing Java sample compiling without credentials.
- Scan tracked files for credentials and run `git diff --check` before commit.
