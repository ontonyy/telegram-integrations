# J07 — Submit a Mini App request to a Java backend

[Русская версия](../../ru/tasks/completed-issues/J07.md) · [GitHub issue #7](https://github.com/ontonyy/telegram-integrations/issues/7)

## What was delivered

The sample has a working Mini App form that submits a synthetic request, returns a reference, and retrieves status only for the request owner.

## How it works

The browser sends raw `Telegram.WebApp.initData`; the backend validates its HMAC and freshness, then derives the Telegram user ID from the signed data. It does not trust `initDataUnsafe` or a browser-supplied ID. `MiniAppRequestService` applies a separate owner check to status reads. Group launch context does not grant shared access or message-history access.

## Use this in a real project

Use a Mini App when a customer or employee needs a validated form, order view, schedule, or richer mobile interface than chat buttons allow. Host it over HTTPS, configure its launch URL, validate every launch server-side, then apply your own account and record authorization. Replace the process-memory store before production.

## Implementation and limits

See [`MiniAppController`](../../examples/java-spring/src/main/java/example/telegram/MiniAppController.java), [`TelegramInitDataValidator`](../../examples/java-spring/src/main/java/example/telegram/TelegramInitDataValidator.java), and [Mini App tests](../../examples/java-spring/src/test/java/example/telegram/MiniAppControllerTest.java). Tests use synthetic signed data; no bot, public Mini App URL, or live Telegram launch was used. Records are capped and lost on restart.
