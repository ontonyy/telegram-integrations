# J21 — Verify J10 upload recovery across separate JVM processes

[Русская версия](../../ru/tasks/completed-issues/J21.md) · [GitHub issue #21](https://github.com/ontonyy/telegram-integrations/issues/21)

## What was delivered

`FileIntakeServiceTest.preservesAndRecoversWorkspaceLeasedByAnotherJvm` starts separate JVM processes that hold upload lease locks in a shared temporary root. It verifies that an intake preserves an active process's synthetic partial file, a later intake removes that workspace after forced process termination, and cleanup preserves a second active process's workspace.

Run it from `examples/java-spring`:

```bash
./gradlew test --tests example.telegram.FileIntakeServiceTest.preservesAndRecoversWorkspaceLeasedByAnotherJvm
```

## Verification and limits

The test uses only synthetic text and local processes; it makes no Telegram calls and uses no credentials. A passing result demonstrates the behavior of the filesystem used for that run only. It does not establish reliable Java `FileLock` behavior on NFS, container volumes or other deployment filesystems. Verify the exact target filesystem before relying on this cleanup mechanism in a shared deployment.
