# J15 — Submit private employee requests for manager approval

[Русская версия](../../ru/tasks/completed-issues/J15.md) · [GitHub issue #15](https://github.com/ontonyy/telegram-integrations/issues/15)

## What was delivered

An employee can start a private bot conversation, submit a short synthetic request, and check its status. A configured manager reviews approve/reject and confirms the chosen action in a second callback.

## How it works

`ConfiguredInternalRoleDirectory` maps server-configured Telegram IDs to employee/manager roles. The service checks those roles on submission, status lookup, action selection, and confirmation. It checks request state, manager identity, configured approval chat, and a ten-minute confirmation token. A bounded UTC audit records submit/decision actor, action, timestamp, and outcome. Request detail is cleared from process state after routing to the approval chat.

## Use this in a real project

Use the flow as a phone-friendly front door for low-risk IT/support requests or approvals. Replace the demo ID list with an independently authenticated employee identity source such as SSO, persist requests and audit in access-controlled storage, and add an outbox/idempotency store. Keep company roles out of Telegram group-admin claims.

## Implementation and limits

See [`InternalRequestService`](../../examples/java-spring/src/main/java/example/telegram/InternalRequestService.java), [`ConfiguredInternalRoleDirectory`](../../examples/java-spring/src/main/java/example/telegram/ConfiguredInternalRoleDirectory.java), and [approval tests](../../examples/java-spring/src/test/java/example/telegram/InternalRequestServiceTest.java). State is in memory and no corporate identity source, HR/ITSM system, internal group, or employee account was connected.
