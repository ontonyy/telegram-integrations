# J12 — Explore TDLib Java authorization without coupling it to Spring

[Русская версия](../../ru/tasks/completed-issues/J12.md) · [GitHub issue #12](https://github.com/ontonyy/telegram-integrations/issues/12)

## What was delivered

An optional standalone Java/JNI example shows TDLib authorization-state handling, client lifecycle, a minimal chat-title listing operation, and local session removal steps. It is isolated from the normal Bot API/Spring sample.

## How it works

The core authorization flow depends on a `TdLibPort`, so fake-port tests can check state transitions without JNI, network access, or credentials. A separate optional source set adapts the official TDLib Java API. The manual client asks for login details interactively and lists at most ten main-list chat titles; it does not retrieve message bodies, index history, send messages, or invoke AI.

## Use this in a real project

Choose TDLib only when you are building a real user-account client. Build the native library for the supported OS/JVM, protect the session database and encryption key, provide logout and Telegram device-revocation guidance, and map account access to explicit application actions. Chat access does not itself authorize external processing.

## Implementation and limits

See the [TDLib README](../../examples/tdlib-java/README.md), [`AuthorizationFlow`](../../examples/tdlib-java/src/main/java/example/telegram/tdlib/AuthorizationFlow.java), and [fake-port tests](../../examples/tdlib-java/src/test/java/example/telegram/tdlib/AuthorizationFlowTest.java). Tests do not build JNI or log into Telegram; no native build or real account session was run.
