# J24 — Offline signed Chatwoot webhook lab

## Delivered

- Added `POST /chatwoot/webhook` for a narrow subset of outgoing Chatwoot events. It verifies HMAC-SHA256 over the timestamp, a dot, and the exact raw body bytes before parsing the event.
- The request filter enforces a configurable Chatwoot body limit before Spring reads the complete request body. The controller keeps a second defensive limit.
- The processor routes only incoming text `message_created` events sent by a contact. It passes conversation/contact references to the handoff; it does not pass message text to that seam.
- Duplicate suppression keys on account ID and message ID inside the signed body. The optional `X-Chatwoot-Delivery` header is correlation metadata only.
- Added fixed synthetic signature vectors, focused controller/processor/filter tests, and `demoChatwootSupport`, which uses only fakes and makes no network calls.

## Boundaries

Chatwoot's built-in Telegram inbox owns Telegram's webhook, Telegram channel delivery, conversation history and operator UI. This Java webhook is a separate Chatwoot-to-application seam. The sample has no Chatwoot API client, credentials, live account setup or live verification. Webhook body content is parsed transiently but not retained by the handoff or fake recorder. The 10,000-entry idempotency registry and handoff state are in-memory and process-local; they are not durable, do not coordinate across instances, and cannot guarantee production idempotency. The five-minute timestamp window limits stale replay but is not a substitute for durable deduplication.

A real deployment would need a shared durable idempotency store with atomic side effects, explicit retry and retention policy, separately authenticated operator actions, network/ingress controls, and a reviewed Chatwoot API integration. Do not infer production readiness from this teaching example.

## Verification

From `examples/java-spring`:

```bash
./gradlew test --tests example.telegram.ChatwootWebhookSignatureValidatorTest --tests example.telegram.ChatwootWebhookControllerTest --tests example.telegram.ChatwootWebhookProcessorTest --tests example.telegram.ChatwootSupportHandoffTest --tests example.telegram.TelegramWebhookBodyLimitFilterTest
./gradlew demoChatwootSupport
./gradlew test
```

The tests and demo use synthetic IDs, text and secrets only. No Telegram or Chatwoot account was connected.
