# J01 — Make the Java examples reproducible without credentials

[Русская версия](../../ru/tasks/completed-issues/J01.md) · [GitHub issue #1](https://github.com/ontonyy/telegram-integrations/issues/1)

## What was delivered

The repository now has a shared Java 25 / Spring Boot example project, synthetic tests, and seams for replacing external HTTP calls with fakes. Telegram and AI credentials are optional; outbound Telegram delivery stays off by default.

## How it works

`HttpTransport` separates service logic from the real `JdkHttpTransport`. Tests inject an in-memory transport or local mock HTTP server. A demo profile supplies only a public local webhook placeholder. The credential scan checks common secret formats and ignores local account/session artifacts.

Run the sample tests from the repository root:

```bash
./examples/java-spring/gradlew -p examples/java-spring clean test
```

## Use this in a real project

Use this structure as the base for another provider adapter: define a narrow transport or gateway interface, test request construction and failures with synthetic data, then add a separately configured live adapter. Keep secrets in environment variables or a secret manager. Replace in-memory state with durable shared storage when multiple instances or restarts matter.

## Implementation and limits

See [the Java/Spring README](../../examples/java-spring/README.md), [`HttpTransport`](../../examples/java-spring/src/main/java/example/telegram/HttpTransport.java), and [external-call boundary tests](../../examples/java-spring/src/test/java/example/telegram/ExternalCallBoundaryTest.java). Local tests do not prove connectivity to Telegram, HubSpot, Jira, Grafana, or an AI provider.
