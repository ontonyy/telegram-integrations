# J02 — Send Bot API messages with Java HttpClient

[Русская версия](../../ru/tasks/completed-issues/J02.md) · [GitHub issue #2](https://github.com/ontonyy/telegram-integrations/issues/2)

## What was delivered

`TelegramBotClient` sends Bot API requests directly with Java's `HttpClient`. The example covers text, HTML-safe notifications, inline keyboards, callback answers, and message edits without requiring a bot framework.

## How it works

The client reads the token from configuration, builds the `/bot<TOKEN>/<method>` request, and sends JSON through `HttpTransport`. `TELEGRAM_SEND_ENABLED` defaults to `false`; enabling delivery without a token fails closed. Unit tests point at a local HTTP server and verify method, path, headers, body, and safe failure handling. The sender does not retry automatically, because a timeout can leave delivery ambiguous.

Run its HTTP tests:

```bash
./examples/java-spring/gradlew -p examples/java-spring test --tests example.telegram.TelegramBotClientHttpTest
```

## Use this in a real project

Use the direct client for a small Java service that only posts build, incident, or business-status notifications. A user must first start the bot or add it to a chat where it can write. Add a bounded retry queue that respects Telegram's `retry_after`, and avoid including logs or personal data in messages.
