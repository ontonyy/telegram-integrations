# J09 — Send Grafana alerts with an application acknowledgement

[Русская версия](../../ru/tasks/completed-issues/J09.md) · [GitHub issue #9](https://github.com/ontonyy/telegram-integrations/issues/9)

## What was delivered

The Java sample receives Grafana alert webhooks, sends concise firing/resolved notifications, and offers an allowlisted Telegram callback to record that an on-call person saw an alert.

## How it works

`POST /grafana/webhook` validates HMAC-SHA256 and timestamp headers, caps the payload size, and formats selected labels and a validated source URL. An authorized user can acknowledge the app's alert record. Repeated acknowledgement is rejected as already handled.

## Use this in a real project

For send-only notifications, Grafana's native Telegram contact point may be enough. Use the Java adapter when you need custom filtering, an app-owned acknowledgement, or another backend action. Configure the Grafana webhook and secret, a Telegram destination, and a narrow manager/on-call allowlist.

## Implementation and limits

See [`GrafanaWebhookController`](../../examples/java-spring/src/main/java/example/telegram/GrafanaWebhookController.java), [`GrafanaAlertService`](../../examples/java-spring/src/main/java/example/telegram/GrafanaAlertService.java), and [Grafana tests](../../examples/java-spring/src/test/java/example/telegram/GrafanaWebhookControllerTest.java). The acknowledgement does not resolve or silence the Grafana alert. State is in memory; tests use synthetic payloads and a fake sender.
