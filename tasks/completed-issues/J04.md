# J04 — Run a group vote with authorized callbacks

[Русская версия](../../ru/tasks/completed-issues/J04.md) · [GitHub issue #4](https://github.com/ontonyy/telegram-integrations/issues/4)

## What was delivered

The bot can open a synthetic scheduling vote in a group, accept per-user inline-button choices, let a voter change a choice, and let only the creator close the vote.

## How it works

`/vote` creates a random vote reference and posts buttons. Each callback is checked against the configured voter allowlist, chat, vote state, and option index. A user has one current choice. The app edits the message with totals; `/closevote <id>` posts final results. Repeated update delivery is handled by the webhook registry.

## Use this in a real project

Use this pattern for team scheduling or another low-risk decision that needs application-managed per-person eligibility. Configure a narrow server-side allowlist and keep the bot in the intended group. If authorization and editable per-user state are unnecessary, prefer Telegram's native poll instead.

## Implementation and limits

See [`GroupVoteService`](../../examples/java-spring/src/main/java/example/telegram/GroupVoteService.java), [`ConfiguredGroupVoteAuthorizer`](../../examples/java-spring/src/main/java/example/telegram/ConfiguredGroupVoteAuthorizer.java), and [vote tests](../../examples/java-spring/src/test/java/example/telegram/GroupVoteServiceTest.java). State is capped in process memory and disappears at restart. The bot does not read arbitrary group history or infer company roles from Telegram group-admin status.
