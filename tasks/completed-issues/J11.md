# J11 — Answer a user's direct AI question with scoped consent

[Русская версия](../../ru/tasks/completed-issues/J11.md) · [GitHub issue #11](https://github.com/ontonyy/telegram-integrations/issues/11)

## What was delivered

The sample can send a user's directly submitted private-chat question to the configured Claude API after disclosure, feature consent, and a separate confirmation for that exact prompt.

## How it works

`/ai-help` discloses provider, purpose, and data boundary. `/consent` records feature consent; `/ask` stages text locally; `/ai-confirm` makes the provider call. `/ai-cancel` discards a staged question and `/stop` revokes consent. `/human` marks a handoff request but does not connect an operator. The prompt is not combined with group messages, files, chat history, Business messages, or other users' data.

## Use this in a real project

Use the pattern for an explicit one-to-one question-answer feature. Before deployment, review current Telegram terms, the provider's retention terms, the privacy notice, and the user's consent scope. Add a real knowledge base only from content the organization is allowed to process. Keep human response separate from model output.

See [`BotReplyService`](../../examples/java-spring/src/main/java/example/telegram/BotReplyService.java), [`ClaudeClient`](../../examples/java-spring/src/main/java/example/telegram/ClaudeClient.java), and [AI consent tests](../../examples/java-spring/src/test/java/example/telegram/AiConsentFlowTest.java).
